# Phase 1 Engineering Plan — "Little One"

Read alongside `MASTER_PROMPT.md` (the product spec). This file is the build plan: exact stack, file tree, module contracts, file ownership for parallel agents, content rules, validation gates, and demo spec. On product/content questions, MASTER_PROMPT.md wins; on code structure, this plan wins.

## Stack: zero-dependency vanilla PWA (binding constraint)

This build environment's network egress policy **blocks registry.npmjs.org, pypi, and all CDNs** (verified: HTTP 403, `x-deny-reason: host_not_allowed`). Therefore:

- **Never run `npm install` / `npx` — there are no dependencies and no registry access.** Do not add package deps; do not fetch anything from the network.
- The app is **plain modern JavaScript (ES2022 modules), hand-written CSS, and static HTML** — no build step, no framework, no Tailwind. The `app/` directory is the deployable site, served as-is.
- Types via **JSDoc annotations** (`@typedef`, `@param`, `@returns`) — every exported function and shared shape is annotated.
- Tests via **`node:test`** (built into Node 22): `node --test test/`.
- PWA bits are hand-rolled: `manifest.webmanifest` + a small explicit-precache `sw.js`.
- Icons are generated by a zero-dependency PNG encoder script using `node:zlib` (PNG = signature + IHDR + IDAT(deflated filter-0 scanlines) + IEND, with a hand-written CRC32).
- Screenshots via headless Chromium CLI at `/opt/pw-browsers/chromium` (verified working) — no Playwright package.
- `package.json` exists only for `"type": "module"` and scripts: `test` (`node --test test/`), `serve` (`node scripts/serve.mjs`), `icons` (`node scripts/generate-icons.mjs`), `shots` (`node scripts/screenshot.mjs`). **No `dependencies` or `devDependencies`.**

This is a deliberate upgrade for this product, not just a workaround: zero supply chain, instant load, trivially hostable on any static host (e.g. GitHub Pages), and fully private.

### `app/js/features/size/silhouettes.js`

```js
/** @typedef {{ id: string, minWeek: number, maxWeek: number,
 *   viewBox: { w: number, h: number },   // arbitrary units
 *   path: string,                        // one closed SVG path, head at top ('M' … 'Z')
 *   crownY: number,                      // top of head, viewBox units
 *   rumpY: number,                       // bottom of rump
 *   lowestY: number,                      // lowest point of the figure (may equal rumpY)
 *   spanFraction: number }} Silhouette */ // share of the week's official length that crownY→lowestY is
export const SILHOUETTES  // ids: embryo, early, mid, late, term — ranges 4–9, 10–19, 20–27, 28–36, 37–42
export function silhouetteForWeek(week)
```

Scaling rule: `span = lowestY − crownY`; `k = (lengthMm × spanFraction × pxPerMm) / span`; render the SVG at `viewBox.w × k` by `viewBox.h × k` CSS px. The measurement basis is **not** a parameter — it is already baked into `spanFraction`.

**Curled-pose honesty rule (replaces the old legs-extended rule).** Every silhouette is drawn in a natural curled fetal pose, because that is how a baby lies; the previous contract forced legs-extended poses from week 20 so `crown → heel` could span the whole drawing, and it made the babies read as standing toddlers. `spanFraction` is what keeps "actual size" true without straightening them: it is the fraction of the week's **official** length that the drawn `crownY → lowestY` span represents.

- Weeks 4–19 are reported **crown-rump**, and crown-rump is measured on exactly this curl, so `spanFraction ≈ 1.0` (shipped: 1.041 embryo, 1.003 early — the drawn span runs a little past the rump, to a tail or a tucked heel). Acceptance band: `[0.95, 1.1]`.
- Weeks 20+ are reported **crown-heel with the legs stretched**, which no curled drawing can span. A curled fetus really does occupy ~66–72% of its stretched length, so `spanFraction ≈ 0.66–0.71` (shipped: 0.705 mid, 0.70 late, 0.66 term). Acceptance band: `[0.6, 0.75]`.

The result is honest in both directions: the figure on the glass occupies exactly the space the curled baby occupies, and the stretched head-to-heel number stays a **stat** rather than a silhouette. The Size screen must therefore never present the two as the same claim — from week 20 the measurement chip names the pose ahead of the number — `"curled up · 20.2 in head to heel"`, one nowrap part so it always renders on a single line and the band under the picture stays exactly two lines tall (the fuller `"… when stretched"` wording took a second line of its own, pushing the band to three lines on 46 of the 78 week/unit combinations and walking the picture and the scrubber ~20 px between weeks) — and the week 19 → 20 note (`BASIS_SWITCH_NOTE`) explains both changes at once: the ruler switches to head-to-heel, *and* the pose shows the baby curled as they really are.

### App composition (`app/js/main.js`)

- Tabs: `'today' | 'size'` (Phase 1); state in main.js; screens receive a context `{ settings, update, go, showSettings }` where `go(tab)` switches tabs and `showSettings()` opens Settings as a full-screen sheet (gear lives in Today's header).
- Gate: `settings.dueDateISO === null` → Welcome screen (no tab bar).
- Each screen module exports `render(ctx)` → `HTMLElement`; main.js swaps `<main>` children on tab change. Fine-grained updates (e.g. a to-do checkbox) must NOT trigger a full re-render (no scroll jump) — update storage and the local DOM node directly.
- Layout: single column, `max-width: 430px` centered; fixed bottom tab bar padded by `env(safe-area-inset-bottom)`; `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`.
- **Demo/dev query params** (parsed once on load, applied, then stripped via `history.replaceState`): `?due=YYYY-MM-DD` seeds the due date · `?reset=1` clears storage · `?tab=size` opens a tab · `?week=40` sets the Size scrubber week · `?pxmm=6.0` seeds calibration.

## Content rules (for the five chunk agents)

Prose rules: warm second person, ~8th-grade level, no fear-mongering, no "always/never/guaranteed" medical claims, **no length/weight numbers in prose** (the UI renders those from `SIZE_TABLE`), milestones placed per MASTER_PROMPT Appendix A anchors, and every fact within Appendix A's guardrails.

2. "Skip high-mercury fish: shark, swordfish, king mackerel, tilefish, bigeye tuna, marlin, and orange roughy. Salmon, sardines, shrimp, cod, and canned light tuna are great picks."
3. "Pass on raw or undercooked meat, poultry, eggs, and sprouts — and sneak-tasting raw cookie dough counts too."

6. "Keep caffeine to 200 mg a day or less — about one 12-oz coffee. Tea, chocolate, and soda count toward the total."

## Validation gates (integrator; all must pass)

1. `scripts/check.sh`: `node --check` on every `.js`/`.mjs` file in `app/`, `scripts/`, `test/` — clean.
2. `node --test test/` green, including `test/content.test.mjs` (written by integrator) asserting (note: this Node treats a path argument as a file pattern and will not walk a directory, so `test/index.js` imports every suite — that is what makes the gate command work; `node --test "test/*.test.mjs"` runs the same suites directly): weeks 4–42 present exactly once across chunks; `baby.length` 2–4 and `body.length` 1–3 with non-empty strings; `eat.length` 4–6; every `safety` exactly matches the rotation formula; all mandatory todo ids present in their weeks; todo ids globally unique and `w{week}-` prefixed; no prose paragraph contains a digit immediately followed by ` in`, ` cm`, ` oz`, ` lb`, ` g` (crude size-leak check); banned phrases absent ("guaranteed", "perfectly safe", "never worry"); `SIZE_TABLE` has all weeks 4–42 and matches Appendix B spot-checks (w17 = 130 CR 140 g, w20 = 256 CH 300 g, w40 = 512 CH 3460 g); every week's silhouette lookup succeeds; the five stages tile 4–42 with no gaps or overlaps; `crownY < rumpY`, `crownY < lowestY ≤ viewBox.h`; `spanFraction` inside `[0.95, 1.1]` for embryo/early and `[0.6, 0.75]` for mid/late/term; every `path` is a non-empty closed path string (starts `M`, ends `Z`/`z`).
3. Serve smoke test: `node scripts/serve.mjs` responds 200 on `/` and on `/js/main.js` with correct MIME (`text/javascript` for `.js`, required for ES modules).

## Demo spec (screenshot agent)

Capture with `/opt/pw-browsers/chromium --headless=new --no-sandbox --disable-gpu --hide-scrollbars --window-size=500,900 --force-device-scale-factor=2 --virtual-time-budget=5000 --screenshot=<path> "<url>"`. - **Verified environment quirk (integrator):** this Chromium clamps its window to a 500 px minimum width. Either shoot at `--window-size=500,900` (the layout is correct; the 430 px column just sits on more background), or drive `Emulation.setDeviceMetricsOverride` over the DevTools protocol for a true 390×844 iPhone viewport (Node 22's global `WebSocket` speaks CDP with no packages). Always open the resulting PNG and look at it.
- Due date for shots: exactly 158 days from today (→ 17w + 3d), computed at runtime.

## Build order

1. **Foundation** (one agent): everything owned by "foundation," including working stubs for all files owned by others. Gates: `node --check` clean, lib tests green, serve smoke OK.
2. **Build** (parallel): Today · Size screen · silhouettes · icons/PWA meta · 5 content chunks. Each agent syntax-checks its own files (`node --check`) and runs `node --test` where relevant, ignoring failures caused by files it doesn't own (other agents are working concurrently).
3. **Integrate**: full gates + content validation suite; fix everything anywhere.
4. **Review** (parallel): medical-content audit vs Appendix A; code review of week math, scaling, calibration, persistence.
5. **Fix**: apply findings; re-run all gates.
6. **Demo**: screenshots for the humans.
